# 衝突編號：CONFLICT-006

## 狀態：`resolved`

## 衝突描述
- **角色 A（平台管理員，代表平台法遵立場）** 需要：依台灣稅法**統一由平台開立電子發票給買家**（spec 安全性需求已明確要求），並以平台名義收取金流、申報營業稅、處理服務費的稅務認列；這是平台合法營運的硬性條件。
- **角色 B（書籍提供者 / 賣家，個人非企業）** 需要：以**個人 C2C 偶發交易者**身分賣出家中閒置書籍，不希望被視為「營業人」而需自行開立發票、申報營業稅、變更為公司／行號身分；其使用情境是「大掃除、搬家、季節整理」等低頻偶發行為，期待的是輕量化體驗。
- **為什麼衝突**：平台若統一向買家開立電子發票，等於平台以「居間銷售方」或「代收代付方」身分介入交易，此時稅務上的銷售額認列方式（平台全額認列 vs 僅認列服務費）會改變平台的營業稅與營所稅成本，也影響賣家是否需要被申報為平台的「個人賣家收入來源」。此衝突直接連動：(a) 平台金流結構與稅務模型；(b) 賣家是否會因被申報所得而卻步；(c) 買家是否能拿到合法可報帳／中獎發票。pre-flag 未列出此項，但 v1.1 同時新增「電子發票」與「平台服務費」兩個決策後此衝突才浮現。

## AI 分析
此衝突屬於 **平台稅務模型 vs 個人賣家輕量體驗** 的張力，是所有 C2C 二手交易平台（蝦皮、旋轉、Carousell）都曾面對的議題。在台灣的稅務脈絡下：

1. **發票開立主體選擇**：平台可採「全額開票模型（平台向買家開立全額發票，賣家收入視為平台支出）」或「服務費開票模型（平台僅就服務費開立發票，書款部分由賣家自行處理）」，兩者在稅務、現金流、賣家體驗上差異極大。
2. **個人賣家所得申報門檻**：依台灣稅法，個人偶發出售自用物品原則上不課所得稅，但若被平台申報為「執行業務所得」或「其他所得」則賣家可能需報稅，這會讓「整理書櫃」的家長卻步。
3. **買家發票需求**：個人買家對發票多半只在意「中獎」與「退換貨憑證」；企業買家則需要「公司抬頭發票」可報帳——但二手書平台的買家以個人為主，此需求較低。
4. **與服務費透明度的耦合**：CONFLICT-002 已指出買賣雙方對價格與服務費的敏感度，發票開立方式會進一步影響賣家「實拿金額」的計算複雜度。
5. **MVP 階段的取捨**：完整稅務模型需法律與會計顧問介入，MVP 初期可能需先選定最簡單可合法營運的方案，預留未來升級空間。

## 解決方案
- [ ] 方案 1（優先滿足角色 A，平台法遵）：採「平台全額開票模型」——平台以居間銷售方身分向買家開立全額電子發票，賣家視為「向平台供貨的個人」，平台統一處理稅務；對賣家明確告知「累積年度收入超過 N 元將依法申報」，並提供下載年度收入報表。法遵清晰但賣家可能因稅務疑慮而卻步。
- [x] **方案 2（優先滿足角色 B，賣家輕量，採用）**：採「服務費開票模型」——平台僅就「平台服務費」部分向買家開立電子發票，書款部分視為賣家與買家之間的個人交易，平台僅作為金流／escrow 服務商。賣家無需擔心被申報所得，但買家拿到的發票金額僅為服務費，且平台需在法律顧問確認下確保此模型符合稅法。
- [ ] 方案 3（折衷分級）：(a) MVP 採「服務費開票」以最小化賣家阻力與法遵風險；(b) 設定賣家年度交易門檻（如 NT$50,000 或 50 本），超過門檻自動升級為「平台代開全額發票 + 年度所得通知」並寄發提醒；(c) 在賣家註冊與刊登流程明確以白話說明發票與稅務的處理方式，避免事後抱怨；(d) 在隱私權／服務條款明列稅務揭露條款。

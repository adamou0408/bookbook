## 可行性評估

### 可行性總評：**Yellow（黃燈）**

核心概念（書籍在家庭之間的循環利用）在台灣市場具備明確需求，技術上完全可實現；但由於「買賣 vs 交流」雙模式未定、且整條技術棧為 0 到 1 建置，涉及金流、信任安全、物流等多個高風險領域，需在 `/req-translate` 與 `/req-plan` 階段仔細切分 MVP 範圍。

### 技術風險
| 風險項目 | 風險等級 | 說明 |
|----------|----------|------|
| 商業模式未定（買賣 vs 交流 vs 混合） | 高 | 直接影響是否需要金流、escrow、發票、消費者保護法遵循；MVP 範圍差異極大。 |
| 金流與第三方支付整合（若採買賣模式） | 高 | 需串接台灣主流金流（綠界、藍新、Stripe TWD）、處理退款、可能需要 escrow/履約擔保以防詐騙。 |
| 信任與安全（Trust & Safety） | 高 | 陌生人交易需身分驗證、評價系統、檢舉機制、書況糾紛處理、兒少保護（若含童書社群）。 |
| 物流與交付方式 | 高 | 需在「超商店到店」、「宅配」、「面交」、「同社區自取」間設計可行流程；涉及運費分攤與交付確認。 |
| 書籍資料與搜尋（ISBN、集數、書況） | 中 | 需外部 ISBN 資料源（Google Books、博客來、國家圖書館 API）以自動補全；搜尋體驗影響使用者好用度甚鉅。 |
| 圖片上傳與儲存（書況照片） | 中 | 物件儲存（S3/GCS）、圖片壓縮、CDN、內容審查（不當內容偵測）。 |
| 使用者帳號與身分驗證 | 中 | 電子郵件 / 手機 / 第三方登入（Google/Apple/Line）；Line 登入在台灣家庭族群滲透率高，強烈建議納入。 |
| 地理位置與在地媒合 | 中 | 依距離排序、區域圈選；涉及 PII（地址）保護，不可精確公開。 |
| 行動優先 UX（「使用者好用」訴求） | 中 | 台灣家庭主要裝置為手機；須決定 PWA / RWD 網站 / Native App，對工期影響顯著。 |
| 個資法遵循（PDPA）與消保法 | 中 | 書籍買賣可能構成商業行為，需隱私權政策、使用條款、未成年人限制、七天鑑賞期處理。 |
| 反詐騙與內容濫用 | 中 | 避免成為盜版書、違禁書、詐騙商品的流通管道，需檢舉與下架機制。 |
| 平台冷啟動（雙邊市場） | 中 | 初期書籍供給不足會直接打擊使用者體驗，需種子策略（例如先聚焦單一社群／家長社團）。 |

## 建議方向
（AI 基於以上分析提出的建議，供人類參考）

### 建議 1：在 `/req-translate` 前釐清三個關鍵決策
為避免 spec 範圍膨脹，建議由需求提出者或 Spec 擁有者先回答：
- **商業模式決策**：MVP 先做「以交換 / 贈送為主」的交流平台（避開金流與消保法風險），還是「以買賣為主」的二手書市集（需金流、escrow、物流）？或兩者混合？
- **MVP 範圍決策**：第一版是否限定特定區域（例如單一縣市或單一社區）以降低雙邊市場冷啟動風險？
- **交付方式決策**：是否限定「超商店到店」作為唯一物流方式，避開面交安全與宅配成本問題？

### 建議 2：推薦的 MVP 切分（Yellow → Green 的路徑）
如果採納以下切分，風險等級可降至 Green：
1. **Phase 1（交流優先）**：純「贈送 / 交換」模式，不含金流。使用者刊登書籍 → 他人索取 → 雙方私訊約定交付 → 平台僅負責媒合與評價。
2. **Phase 2（加入買賣）**：待 Phase 1 建立信任與流量後，再引入付費模式與金流整合。
3. **Phase 3（規模化）**：加入地理搜尋、推薦演算法、社群功能。

此切分可讓第一個 spec 聚焦於：使用者帳號 + 書籍刊登 + 搜尋 + 索取/配對 + 評價 + 基本檢舉機制，技術複雜度可控。

### 建議 3：技術選型建議（供 `/req-plan` 參考）
- **前端**：Next.js / React + Tailwind，優先 RWD 網站；若資源允許可追加 PWA 以提供類 App 體驗。
- **後端 / 資料庫**：PostgreSQL（支援地理查詢、全文檢索）+ 任一主流框架（Next.js API Routes / NestJS / Fastify）。
- **認證**：第三方登入優先整合 Line（台灣家庭族群高滲透率）+ Google。
- **物件儲存**：Cloudflare R2 / AWS S3 + CDN。
- **書籍資料**：串接 Google Books API 或博客來資料，以 ISBN 自動補全。
- **部署**：單一 PaaS（Vercel / Fly.io / Railway）降低 infra 複雜度，待規模擴大再遷移。

## 下游摘要
- **核心需求**：為台灣家庭打造一個書籍買賣或交流平台，讓使用者能以最低成本流通家中閒置書籍、接觸更多完整集數的書籍，並強調使用者體驗要好用。
- **關鍵約束**：
  1. 商業模式（買賣 vs 交流）尚未決定，直接影響金流與法遵範圍。
  2. 「使用者好用」尚無具體可量測指標，需在 spec 階段定義。
  3. Host repo 為 greenfield，無既有技術棧可複用，全部需從零建置。
- **風險項目**：
  1. 金流 + 物流 + 信任安全（若採買賣模式）屬高風險三角，MVP 建議先避開。
  2. 雙邊市場冷啟動（供給不足會直接打擊使用者體驗），需種子策略。

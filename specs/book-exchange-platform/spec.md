## * 需求摘要

為**所有台灣讀者**打造一個**二手書買賣市集**，讓書籍擁有者能快速刊登家中閒置書籍、書籍需求者能以比新書更低的成本購入所需書籍（特別是圖書館借不到的缺集、絕版書、完整套書）；MVP 第一版採**全台同步上線**，交付方式**僅限超商店到店**，產品核心訴求是「使用者好用」——具體定義為：瀏覽／搜尋不需登入、註冊 ≤ 90 秒、完成一本書刊登 ≤ 2 分鐘、搜尋結果 P95 ≤ 1 秒。

> 📌 **v1.1 範圍決策**（取代 v1.0 的開放問題）：
> - **商業模式**：純買賣（二手書市集），含第三方金流、escrow、發票、7 天鑑賞期。
> - **目標族群**：所有台灣讀者（家庭讀者仍為核心 persona，但不排除學生、社會新鮮人、一般個人讀者）。
> - **物流**：僅支援超商店到店（不支援宅配與面交）。
> - **上線範圍**：MVP 即全台同步上線（不做區域試點）。

## * 使用者故事

### 角色 A：家長讀者（[personas/family-reader.md](../../personas/family-reader.md)）

- **作為**家長讀者，**我想要**以低於新書的價格買到整套童書或補齊某套童書缺少的集數，**以便**為孩子安排連貫的親子共讀。
- **驗收條件**：
  - [ ] 我可以使用「書名」「作者」「系列名」「ISBN」其中任一搜尋條件查找書籍。
  - [ ] 搜尋結果可依「同系列剩餘集數」「距離我最近的超商」「總成本最低（書價＋運費）」三種方式排序。
  - [ ] **書況詳實徽章**（CONFLICT-003 決議）：我可以在搜尋結果中識別「書況詳實」徽章（上傳 ≥ 3 張書況照片的賣家），優先選擇資訊完整的刊登。
  - [ ] 我可以將特定書籍或系列加入「追蹤清單」，當有人新刊登符合條件的書籍時平台會主動推播通知。
  - [ ] 購買書籍後可在「我的訂單」追蹤狀態（已付款／賣家出貨中／到店待取／已取貨／已完成）。
  - [ ] 我可以在取書完成後對賣家給予 1–5 星評價與文字評論。
  - [ ] 在交易完成前，我與賣家的真實姓名、地址、電話皆不互相揭露；僅透過站內訊息與超商店號溝通。

### 角色 B：書籍提供者（賣家）（[personas/book-provider.md](../../personas/book-provider.md)）

- **作為**書籍提供者，**我想要**用最少的步驟刊登家中閒置書籍並以合理價格賣出，**以便**快速清空書櫃、回收部分成本，並讓書籍流通到真正想閱讀的人手中。
- **驗收條件**：
  - [ ] 我可以使用條碼掃描（ISBN）自動補全書名、作者、出版社、封面，無需手動輸入書籍基本資料。
  - [ ] 對於沒有 ISBN 或掃描失敗的書，我可以手動輸入書名／作者並上傳自拍封面。
  - [ ] 我可以一次選取多張書況照片並上傳，系統自動壓縮並產生縮圖。
  - [ ] **書況極簡勾選**（CONFLICT-003 決議）：基本要求 1 張封面照 + 三段式書況勾選（良好／普通／明顯瑕疵）；書況照片 ≥ 3 張的刊登可在搜尋結果獲得「書況詳實」徽章與排序加分（鼓勵而非強制）。
  - [ ] **分級刊登**（CONFLICT-001 + CONFLICT-003 協同決議）：低風險類別（一般小說、自我成長書等）刊登維持極簡流程；高風險類別（童書、教材、漫畫、絕版書）在**單一補件步驟**中系統自動要求：
    - CONFLICT-001：加拍「版權頁照片」 + 填寫「版次／出版社」欄位
    - CONFLICT-003：童書類別額外必填「內頁書況照」並提示「家長讀者會特別檢查書況」
    - UI 明示「此類書需額外資訊以保障雙方權益」，避免賣家被連續兩次要求補件
  - [ ] 從開始刊登到送出，單本書完整流程（含掃碼、拍照、填寫書況、定價、確認上架）**平均時間 ≤ 2 分鐘**（不含照片拍攝時間；高風險類別目標 ≤ 3 分鐘）。
  - [ ] 我可以自行設定售價，並參考「建議售價」提示（CONFLICT-002 決議：資料源為「新書定價 × 建議折數區間」；MVP 初期以此作為冷啟動錨點）；超過建議售價上限仍可送出，系統加註「偏高」提示。
  - [ ] **雙顯示**（CONFLICT-002 決議）：定價介面同步顯示「買家看到的總成本（書價 + 運費）」與「賣家實拿金額（售價 − 平台服務費）」，金流透明化。
  - [ ] 收到訂單後，平台以站內訊息與推播雙重提醒我出貨。
  - [ ] 我可以在平台指定「寄件超商店號」，系統產生出貨單並提示我上傳寄件編號。
  - [ ] **escrow 自動撥款 + 提早結案**（CONFLICT-005 決議）：
    - 預設：買家付款 → 平台 escrow → 買家確認取貨 + 7 天鑑賞期結束 → 款項自動撥入賣家帳戶（扣除平台服務費）。
    - 提早撥款：鑑賞期內買家若點選「確認無誤、提早結案」按鈕，立即觸發全額撥款（無需等滿 7 天）。
    - 在刊登介面預先揭露「預估到帳日」，管理賣家期待。
    - 信用分數機制預留欄位（MVP 不啟用），未來可依累積交易資料啟動「快速撥款方案」。

### 角色 C：書籍需求者（買家）（[personas/book-seeker.md](../../personas/book-seeker.md)）

- **作為**書籍需求者，**我想要**用比購買新書更低的成本買到想看的書，**以便**在預算有限的情況下持續閱讀更多書籍。
- **驗收條件**：
  - [ ] **瀏覽與搜尋完全不需要登入或註冊**；登入僅在發出購買、刊登、檢舉時要求。
  - [ ] 註冊流程（含身分驗證與取書超商設定）從進入註冊頁到完成總時長 **≤ 90 秒**。
  - [ ] 搜尋結果回應時間 **P95 ≤ 1 秒**（一般文字搜尋條件）。
  - [ ] 每筆書籍刊登都明確顯示「總成本」（書價 + 超商店到店運費），絕不在後續流程出現未揭露費用。
  - [ ] **多排序**（CONFLICT-002 決議）：搜尋結果提供「總成本最低」「書況最佳」「距離最近」三種並列排序，由買家自行切換。
  - [ ] 我可以在站內訊息中與賣家確認書況，全程不需透露真實姓名與聯絡方式。
  - [ ] **我的個資存取紀錄**（CONFLICT-004 決議）：我可以在個人頁自助查閱「誰（哪個層級的管理員）、什麼時候、為什麼存取了我的個資」；每筆第三方揭露（警方、稅捐機關）除法律明文禁止通知者外均會事前或事後通知我。
  - [ ] 付款完成後可在「我的訂單」追蹤到貨狀態。
  - [ ] 收到書後享有 **7 天鑑賞期**，可於期內回報書況落差並發起爭議；爭議成立時由平台從 escrow 退款。
  - [ ] **提早結案按鈕**（CONFLICT-005 決議）：在鑑賞期內、取貨後 **至少 24 小時後**，可主動點選「確認無誤、提早結案」立即完成交易並觸發賣家全額撥款。此按鈕**預設隱藏至 24 小時後才顯示**，避免賣家施壓買家提前點選。
  - [ ] 完成交易後可對賣家給予評價，並有機會留下文字回饋。

### 角色 D：平台管理員（[personas/platform-admin.md](../../personas/platform-admin.md)）

- **作為**平台管理員，**我想要**一個集中後台處理檢舉、糾紛、內容下架與 escrow 撥款，**以便**維持平台的內容品質與交易信任。
- **驗收條件**：
  - [ ] 後台顯示所有待處理檢舉與糾紛的優先順序佇列（依嚴重度與時間排序）。
  - [ ] 我可以一鍵下架違規刊登，並自動通知該賣家下架原因。
  - [ ] **風險分級管理**（CONFLICT-001 決議）：我可以維護「高風險書籍類別清單」（預設含童書、教材、漫畫、絕版書），並可新增／調整；高風險類別刊登會自動進入「複審佇列」，我可依優先序逐筆核准／下架／要求補件。
  - [ ] **分層 RBAC**（CONFLICT-004 決議）：後台角色分三層——(a) **客服一線**只看暱稱、訂單編號、站內訊息，真實姓名／地址／電話全遮蔽；(b) **資深客服**可在個案中點開原始個資，每次點開自動寫入審計日誌並通知當事人；(c) **法遵專員**可匯出個資供第三方揭露，需主管核准。MVP 階段可先實作「一線／法遵」兩層，預留「資深客服」欄位。
  - [ ] 我可以查閱任一筆交易的完整審計日誌（站內訊息、狀態變更、付款／出貨／取貨／鑑賞期／撥款紀錄）。
  - [ ] 我可以在爭議成立時主動從 escrow 退款給買家，並在系統留下決策原因與證據連結。
  - [ ] 我可以暫停或永久封鎖違規帳號，並記錄決策執行者與時間。
  - [ ] 後台具備指標儀表板：活躍使用者數、新增刊登數、成交數、GMV、糾紛率、首次刊登流程完成率、註冊完成率。
  - [ ] 所有後台操作均寫入審計日誌，可追溯每一筆決策。

## 衝突標記（選填）

v1.1 版本決策後的衝突狀態（6 項全數已解決）：

- ✅ 書籍提供者想要極簡刊登流程（角色 B），但平台管理員需要足夠的審核資訊以避免盜版／違禁書（角色 D）→ [CONFLICT-001](../../conflicts/CONFLICT-001.md) — **已解決：方案 3（分級審核）**
- ✅ 書籍需求者希望以最低成本購入（角色 C），但書籍提供者希望合理回收成本（角色 B）→ [CONFLICT-002](../../conflicts/CONFLICT-002.md) — **已解決：方案 3（折衷：冷啟動錨點 + 雙顯示 + 多排序）**
- ✅ 家長讀者希望書況描述極為詳細（角色 A），但書籍提供者希望刊登流程簡單快速（角色 B）→ [CONFLICT-003](../../conflicts/CONFLICT-003.md) — **已解決：方案 3（折衷，與 CONFLICT-001 協同）**
- ✅ 書籍需求者希望全程不透露個資（角色 C），但平台管理員需要在糾紛時聯絡到當事人（角色 D）→ [CONFLICT-004](../../conflicts/CONFLICT-004.md) — **已解決：方案 3（分層 RBAC + 使用者可查的個資存取紀錄）**
- ✅ **新增（v1.1）**：買家希望 7 天鑑賞期並可隨時退款（角色 C），但賣家希望盡快收款以確認交易（角色 B）→ [CONFLICT-005](../../conflicts/CONFLICT-005.md) — **已解決：方案 3（折衷分階段：預設 7 天 + 提早結案按鈕）**
- ✅ **新增（v1.1，detector 補抓）**：平台依稅法須統一開立電子發票並認列金流（角色 D 法遵立場），但個人賣家為偶發交易者不希望被視為營業人或被申報所得（角色 B）→ [CONFLICT-006](../../conflicts/CONFLICT-006.md) — **已解決：方案 2（服務費開票模型，需法律顧問驗證）**

## * 非功能需求

- 效能：
  - **搜尋結果回應時間 P95 ≤ 1 秒**（一般文字搜尋條件）。
  - **註冊流程總時長 ≤ 90 秒**（從進入註冊頁到完成，含第三方登入與取書超商設定）。
  - **單本書刊登流程總時長 ≤ 2 分鐘**（不含照片拍攝時間）。
  - 書籍列表頁首屏載入時間 P95 ≤ 2 秒（行動網路 4G 條件）。
  - 圖片上傳成功率 ≥ 99%，單張壓縮後 ≤ 300KB。
- 相容性：
  - 行動裝置優先（Mobile-first），需支援 iOS Safari、Android Chrome 最近兩個主要版本。
  - 桌面瀏覽器：Chrome、Edge、Firefox、Safari 最近兩個主要版本。
  - 語系：繁體中文（台灣）為主，介面文案需在地化。
  - **瀏覽與搜尋完全不需登入**（未登入使用者即可看到所有刊登與書況照片）。

## * 安全性需求

- 資料分類：
  - 公開：書籍刊登內容（書名、書況、售價、封面照片）、賣家公開暱稱與信用評價。
  - 內部：使用者行為紀錄、檢舉紀錄、平台指標、交易狀態。
  - 機密：使用者帳號資料、站內訊息、訂單紀錄、超商店號。
  - 高度機密：個資（真實姓名、地址、電話）、金流／escrow 資訊、發票資訊。
- 認證需求：
  - **瀏覽與搜尋不需登入**；發出購買、刊登、檢舉、評價、個資操作皆需登入。
  - 推薦整合 Line 與 Google 第三方登入（台灣讀者族群滲透率高）。
  - 平台管理員後台需獨立的管理員帳號與二因素驗證。
- 授權需求：
  - 一般使用者：刊登／搜尋／購買／評價／檢舉／個人訂單管理。
  - 平台管理員（**分層 RBAC**，CONFLICT-004 決議）：
    - **一線客服**：查閱暱稱、訂單編號、站內訊息、訂單狀態；真實姓名／地址／電話全遮蔽。
    - **資深客服**：在個案中可點開原始個資欄位，每次存取自動寫入審計日誌並通知當事人；可執行下架、封鎖、基本退款。
    - **法遵專員**：可匯出個資供第三方（警方、稅捐機關、金流業者）揭露，需主管核准；建立第三方揭露 SOP 與當事人通知機制（除法律明文禁止通知者外）。
  - 所有角色權限以 RBAC 實作，未授權操作回傳 403 並記錄。
- 加密需求：
  - 全站 HTTPS（HSTS 強制）。
  - 密碼採用業界標準雜湊演算法（bcrypt / argon2）儲存，禁止明文。
  - 高度機密欄位（地址、電話、金流資訊）資料庫層級加密儲存。
  - 金流整合遵循 PCI-DSS 相關要求（實務上由第三方金流業者處理 PCI 範圍）。
- 審計日誌：
  - 必記錄：訂單狀態變更、付款、escrow 撥款、鑑賞期到期、爭議處理、後台下架／封鎖、登入失敗、權限變更。
  - 日誌保存期限 **≥ 1 年**，以符合可追溯性與稅務／法規要求。
- 個資處理：
  - 遵循台灣個人資料保護法（PDPA）最小必要原則，需明確的隱私權政策與使用者同意機制。
  - 真實姓名、地址、電話僅在賣家出貨到指定超商時由平台使用，**絕不揭露給對方使用者**；買家僅看到取貨超商店號。
  - **使用者可自助查閱個資存取紀錄**（CONFLICT-004 決議）：在個人頁可查看「誰、什麼時候、為什麼存取了我的個資」，包含管理員層級與事由。
  - 提供使用者「下載個資」與「刪除帳號」的自助介面。
  - 未成年人（< 18 歲）需家長同意機制。
  - **消費者保護法遵循**：提供明確的退款政策、7 天鑑賞期條款、客訴專線。
  - **電子發票（CONFLICT-006 決議：服務費開票模型）**：
    - 平台定位為「金流／escrow 服務商」而非「送售商」。
    - 平台僅就「平台服務費」部分向買家開立電子發票；書款部分視為賣家與買家之間的個人交易，平台不以居間銷售方身分開立全額發票。
    - 賣家無需自行開立發票，亦不會被平台申報所得。
    - **⚠️ 前置檢查點**：`/req-plan` 階段啟動前必須由法律／會計顧問確認此模型符合台灣《加值型及非加值型營業稅法》、《統一發票使用辦法》、《電子發票實施作業要點》。若顧問否決，必須回頭重新決策 CONFLICT-006。
